# BMS hardened requirements (L2-oriented draft)

Generated by `requirements_hardening` from `inputs/requirements/samples/bms_requirements.csv`.
The original input is unchanged. This folder is a review draft, not a certified baseline.

## Files

| File | Purpose |
|---|---|
| `bms_requirements_hardened.csv` | Compatibility CSV for the existing MUD_MUT importer. |
| `bms_requirements_extended.json` | Full canonical schema (acceptance criteria, trace, open issues). |
| `bms_requirements_extended.csv` | Human-readable flattened view. |
| `test_design.csv` | Test design table with boundary values. |
| `trace_matrix.csv` | Requirement → parent → design → test; includes split mapping. |
| `change_log.md` | New and changed requirements, including split IDs. |

## Split mapping

17 compound requirements were split into 20 atomic parts. The original ID keeps part 1;
parts 2+ use `REQ-BMS-1001..REQ-BMS-1020`. Use `Split_From` / `Split_Into` in `trace_matrix.csv` or the
`split_from` / `split_into` fields in `bms_requirements_extended.json` to follow the mapping.
